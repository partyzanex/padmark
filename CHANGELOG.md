## TL;DR про совместимость с v0.1.6

Это **несовместимый** релиз. Обновление «на месте» без подготовки сломает инсталляцию v0.1.6.

| Что | Эффект при апгрейде с v0.1.6 |
|---|---|
| **Все существующие заметки теряются.** Миграции `20260519000001` и `20260604000001` ставят `expires_at = now()` всем заметкам: v0.1.6 хранил plaintext с открытыми slug, новая схема хранит хешированные slug и зашифрованный контент, старые строки не расшифровать и не найти. Удаляются при следующем обращении. | Обратного пути нет (Down у миграции no-op). Перед апгрейдом выгрузить нужные заметки через `GET /notes/{id}` и пересоздать. `encryption migrate` тут не поможет, он для промежуточных сборок с нешифрованным envelope, не для v0.1.6. |
| **Keyring обязателен.** `PADMARK_CONTENT_KEYRING_FILE` / `--content-keyring-file`, создаётся `padmark-server encryption keygen`. | Без него `serve` не стартует. Файл должен быть `0600`/`0400`, иначе отказ (кроме `/run/secrets/` или `--allow-shared-keyring`). Бэкапить отдельно от БД, потеря ключа = потеря контента. |
| **`--auth-tokens` и `--cookie-max-age` удалены.** Заменены системой аккаунтов (`--enable-accounts`, TOTP, API-токены). | Флаг в командной строке → `flag provided but not defined`, старт падает. **Переменная `PADMARK_AUTH_TOKENS` молча игнорируется**: сервер поднимется полностью публичным, анонимная запись разрешена. Проверить окружение до деплоя. |
| **API: `private: bool` заменён на `privacy: public\|authenticated\|owner`.** Поле `private` исчезло из ответов. | Клиент, шлющий `private: true`, получит не ошибку, а **публичную заметку** (ogen пропускает неизвестные поля). Клиенты, читающие `private` из ответа, увидят отсутствие поля. Колонка `private` в БД удаляется миграцией `20260723000001` безвозвратно. |
| **Миграции схемы применяются автоматически при `serve`**, 16 новых, несколько необратимых (drop `private`, хеширование токенов). | Сделать бэкап БД до первого запуска новой версии. |
| **`edit_code` при создании: 8–128 символов.** | `POST /notes` с коротким кодом → `400/422`. Проверка старых кодов не изменилась. Для v0.1.6 неактуально, заметки всё равно истекут. |
| **SQLite-файл приводится к `0600`**, включая `-wal/-shm`. | Если chmod невозможен, старт отказывается. Другие процессы, читавшие файл по group-правам, потеряют доступ. |
| **Postgres DSN только URL** (`postgres://`, `postgresql://`, `unix://`). | key=value DSN отвергается на старте с ошибкой без пароля. Раньше такой DSN ронял процесс паникой с паролем в выводе. |
| **Go 1.27.3, образ `golang:1.27.3-alpine` → `scratch`.** | Пересобрать образ. `make lint` требует golangci-lint v2.15+. |
| Защитные заголовки и CSP ужесточены, `/api` больше не грузит Redoc с CDN. | Прокси, переписывающие CSP, проверить. Поиск в Redoc требует `worker-src blob:`, его нет, поиск в доке не работает (и раньше не работал). |

Что **не** изменилось: адреса, лимиты по умолчанию (`--rate-limit 10`, `--rate-burst 20`, таймауты, 4 MB body), `--allowed-hosts` пустой = прежнее поведение, `--enable-accounts` по умолчанию выключен, то есть без явного включения сервер остаётся полностью публичным, как v0.1.6 без `--auth-tokens`.

## Новое

**Аккаунты и доступ** (`--enable-accounts`)
- Пользователи с паролем (argon2id) и TOTP, первый админ через `/setup` с `PADMARK_BOOTSTRAP_TOKEN` (≥32 символа, только env). Инвайты одноразовые, живут 24 ч. Сессии в cookie, `--session-ttl` 30 дней.
- `/admin`: инвайты, API-ключи (Bearer для CLI/MCP, `/api/tokens`), отзыв пользователей с каскадом. `/change-password` с TOTP, гасит остальные сессии и ключи. Повторный логин отзывает старую сессию, на `/admin` и `/change-password` есть выход.
- Headless-провижининг: `padmark-cli setup`, `create-token`, `create-invite`, JSON `/setup`, `/api/tokens`, `/api/invites`.
- Уровни приватности `privacy: public | authenticated | owner` для заметок и ссылок. Владелец редактирует и удаляет свои заметки без `edit_code`. Анонимные мутации ограничены тем, что аноним мог бы прочитать.
- `--disable-api`: выключатель REST/JSON (`503`), веб-интерфейс продолжает работать.

**Короткие ссылки**
- `/links`, `/links/bulk`, `GET/PUT/DELETE /links/{id}`, редирект `/r/{id}`. Та же модель edit_code / владение / приватность / burn-after-click, что у заметок.
- Interstitial-страница вместо мгновенного редиректа для анонимно созданных ссылок по умолчанию (`--direct-redirect false`), чтобы инстанс не был открытым редиректором. Prometheus-метрики на отдельном `--metrics-addr`.

**Шифрование контента at rest**
- Контент заметок и целевые URL ссылок шифруются AES-256-GCM под случайным data key, который заворачивается активным ключом инсталляции из keyring. Slug больше не участвует в выводе ключа, поэтому появились `--custom-slugs` (человекочитаемые slug с `/` и `.`).
- Команды `encryption keygen | status | migrate | register | activate | rewrap | convert | retire` для ротации ключей. `serve` проверяет реестр ключей и envelope до открытия портов.
- Session ID, инвайты, reveal-токены burn-after-reading хранятся только как SHA-256.

**Агентная поверхность**
- `padmark-mcp`: stdio MCP-прокси к серверу. `/llms.txt` как машиночитаемое описание. `padmark-cli` получил `--allow-insecure-http`, по умолчанию токен по plain HTTP на не-loopback хост не уходит.

**Эксплуатация**
- `--public-scheme https` включает `Secure` на cookie и HSTS. `--allowed-hosts` теперь работает и на основном listener (`421`), `/healthz` и `/readyz` исключены. `--trusted-proxies` предупреждает о неверной конфигурации. `--csrf-secret` настраиваемый.
- `--argon2-memory/time/threads` и новый `--argon2-memory-budget` (128 MiB): общий лимит памяти на параллельные argon2-деривации. README: секция сайзинга памяти, для контейнера 256 MB нужен `GOMEMLIMIT≈200MiB`.
- Шрифты и Redoc захостены локально, никаких внешних CDN. docker-compose с секретом keyring, `.env.example` описывает все переменные.

## Исправления безопасности (по результатам аудита)

Критичных нет. Высокие:
- 13 уязвимостей stdlib Go 1.26.x закрыты переходом на 1.27.3, зависимости обновлены, `govulncheck` чистый.
- Burn-after-reading: HTML-only interstitial и reveal-токены, чтобы заметка не сгорала от `<img src>` или `Accept: */*`.

Средние:
- Per-username lockout на `/totp-login` и логин: 10 неудач, 5 минут, независимо от IP. Lockout больше не вытесняется из кэша спреем 10 000 ключей.
- Пользовательские `edit_code` хешируются argon2id на настроенной стоимости, минимум 8 символов. Lockout по неверному коду считается по `{ресурс, вызывающий, IP}`, а не глобально по ресурсу.
- Keyring с правами шире `0600` отвергается. SQLite-файл `0600`.
- Процесс-wide бюджет памяти argon2: без него 4 параллельных `POST /notes` с `edit_code` убивали сервер в 256 MB контейнере через OOM.
- CSRF-токен привязан к сессии, формы проверяют `Origin`/`Sec-Fetch-Site`. Дублирующиеся cookie `padmark_session`/`padmark_csrf` (cookie tossing с соседнего поддомена) считаются неоднозначными и отвергаются.
- Пароль Postgres DSN не попадает в ошибки, панику и логи при неверном DSN.

Низкие и прочее:
- CSP: `base-uri 'none'`, `form-action 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, nonce на скрипты. Markdown id получают префикс `user-content-` против DOM clobbering.
- `edit_code` не принимается в query string `DELETE`. Username уникален без учёта регистра (миграция падает, если уже есть коллизии, и ничего не меняет). Стоимость argon2 из БД выше потолка отвергается до аллокации.
- Контент заметки ограничен 1 MiB, рендер кэшируется (128 записей, 2 минуты). Парсер goldmark защищён от квадратичных входов (вложенные `>`, длинные `*`/`_`/`~`, `](`), один 255 KiB документ больше не занимает ядро на минуты.
- Decode-ошибки ogen не светят внутренности, `415` документирован. Anonymous intruder на приватную заметку получает `403`, а не редирект на `/login`. TOCTOU-гонка slug между заметками и ссылками закрыта. SQLite-транзакции `BEGIN IMMEDIATE`.

## Чек-лист апгрейда с v0.1.6

1. Выгрузить нужные заметки, они не переживут миграцию.
2. Бэкап БД.
3. `padmark-server encryption keygen --key-id k1 --output <путь>`, `chmod 600`, прокинуть `PADMARK_CONTENT_KEYRING_FILE`.
4. Убрать `--auth-tokens` / `PADMARK_AUTH_TOKENS` и `--cookie-max-age`. Если нужна авторизация: `--enable-accounts`, `PADMARK_BOOTSTRAP_TOKEN`, затем `/setup` или `padmark-cli setup`, затем снять bootstrap token из окружения.
5. Обновить клиентов API: `private` → `privacy`, `edit_code` ≥ 8 символов.
6. В контейнере с лимитом памяти задать `GOMEMLIMIT` ≈ 75–80 % лимита и при необходимости `PADMARK_ARGON2_MEMORY_BUDGET`.
7. За reverse proxy: `--trusted-proxies`, `--public-scheme https`, `--allowed-hosts`.
8. Запустить `serve`, миграции применятся сами, проверить лог на ошибки реестра ключей.
